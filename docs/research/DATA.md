# Data provenance and reconstruction

An open-source implementation does not make all its input data open. Dataset redistribution permissions still need review.
This repository contains third-party caches; do not assume their presence establishes a license to redistribute them in an app or public API.

## Existing dependencies

| Input | Use | Limitation |
| --- | --- | --- |
| `lab/hist_long.json` | Raw cached testfol.io historical series | Third-party SIM assumptions and data rights; not independently observed ETF history |
| `strategy/data_portfolios.json` | Portfolio histories on the pre-1972-extension calendar | Generated by `strategy/fetch_data.py`; remote API behavior and latest date can change |
| `strategy/data_indicators.json` | CPI, T-bills and market indicators | Same external pipeline; time alignment and vintage must be recorded |
| `strategy/data_portfolios_1972.json` | Extended portfolio histories | Generated by `strategy/history70s.py`; reconstructed early history |
| `lab/clean_1972.json` | Component histories for searches | Generated by `lab/build_1972.py`; proxy and survivorship risks |
| `results/portfolios.json`, `results/improve_best.json` | Definitions and selected reference | Selected using historical data; must be frozen per experiment |

The application currently needs generated strategy inputs that are gitignored. A fresh checkout is not automatically runnable.
The snapshot tool checks them without importing the simulator. Existing reconstruction entry points are:

```bash
python3 strategy/fetch_data.py       # network requests; rebuilds portfolio and indicator inputs
python3 strategy/history70s.py       # extends the portfolio calendar
python3 lab/build_1972.py            # reconstructs component dataset
```

These commands describe the current dependency chain, not a guarantee of historical bit-for-bit reproduction. Remote responses
may change or be unavailable. Retain permitted snapshots and their hashes for a particular result. `lab/make_data.sh` covers
other lab datasets and does not replace the strategy pipeline above.

## Proxy assumptions worth challenging

The managed-futures history before the KMLM SIM series is a time-series momentum reconstruction, with a haircut calibrated using
later overlap. DBMF early history uses a volatility-matched mixture of managed futures and T-bills. Early Nasdaq, bond and
commodity series use other sectors or funds in places. See `strategy/history70s.py` and `strategy/b40_risk.py` for exact splices.
Later-overlap calibration is a potential source of hindsight. Do not describe the whole 1972–2026 range as live ETF performance.

The return-stacked RSST approximation is deliberately tested with a pessimistic cost variant because its live overlap diverged.
Fund fees, financing, distributions, tax character and execution friction are assumptions that must be versioned, not timeless facts.

## Data work that unlocks a public resource

Inventory each series' provider, URL, retrieval date, license/terms, usable date range, adjustment convention and hash.
Replace unclear-redistribution inputs with permissioned sources or reproducible user-supplied downloads.
Validate source replacements by period and regime; do not just match the full-period CAGR.
`engine/data/sources.py`, `engine/sims.py` and `engine/README.md` are the starting point for the independent data pipeline.
